## 一、项目架构

```
┌─────────────────────────────────────────────────────────┐
│                      前端（另有项目）                      │
│              会员端（小程序/H5） + 管理端（Web）            │
└──────────────────────┬──────────────────────────────────┘
                       │ HTTP/SSE
┌──────────────────────┴──────────────────────────────────┐
│                   Controller 层                          │
│  ┌─────────────────────┐  ┌──────────────────────────┐  │
│  │  api/controller/    │  │  admin/controller/       │  │
│  │  会员端接口（无需登录）│  │  管理端接口（需ADMIN角色） │  │
│  │  会员端接口（需登录）  │  │                          │  │
│  └──────────┬──────────┘  └────────────┬─────────────┘  │
│             │                          │                 │
├─────────────┴──────────────────────────┴────────────────┤
│                    Service 层（业务逻辑）                  │
│     AuthService │ XxxService │ SmsService │ AIService    │
├──────────────────────────┬───────────────────────────────┤
│                    Mapper 层（数据访问）                    │
│            XxxMapper.java + XxxMapper.xml                │
├──────────────────────────┴───────────────────────────────┤
│                       MySQL + Redis                       │
└──────────────────────────────────────────────────────────┘
```

### 分层职责

| 层 | 目录 | 职责 |
|---|---|---|
| Controller | `api/controller/`、`admin/controller/` | 接收请求、参数校验、返回响应 |
| Service | `core/service/` | 业务逻辑、事务管理 |
| Mapper | `core/mapper/` | 数据库操作 |
| POJO | `core/pojo/` | 实体类，映射数据库表 |
| Common | `core/common/` | 通用类（Result、PageResult） |

## 五、关键技术决策

### 5.1 认证方案
```
Access Token（2小时）  →  存Redis，用于接口鉴权
Refresh Token（7天）   →  存数据库，用于刷新Access Token

流程：
  登录 → 返回 AccessToken + RefreshToken
  请求 → 带 AccessToken → 拦截器校验
  过期 → 用 RefreshToken 换新的 AccessToken
  登出 → 删除 Redis 中的 AccessToken + 数据库中的 RefreshToken
```

### 5.2 角色鉴权
```
/api/auth/**       → 无需登录
/api/admin/**      → 需要 ADMIN 角色
/api/**            → 需要登录（MEMBER 或 ADMIN）
```

### 5.3 AI对话（SSE流式）
```java
// 使用 Spring AI 的 Flux 流式返回

    // 1. 保存用户消息到数据库

    // 4. 返回 SSE 流
}
```

### 5.4 短信验证码（模拟）
```
开发阶段：验证码打印到日志，固定用 123456
生产环境：对接阿里云/腾讯云短信SDK
```

### 5.5 文件上传
```
体检报告PDF → 上传到本地 /uploads/ 目录
头像 → 上传到本地 /uploads/avatar/ 目录
返回可访问的 URL
```

### 5.6 定时任务
```
- 每小时：清理过期验证码
- 每天：清理过期RefreshToken
- 每天：清理过期AI对话（保留最近30天）
- 每天：更新预约时段状态（过期关闭）
- 活动开始前1天：发送提醒消息
```

## 六、代码规范

### 6.1 命名规范
```
Controller:  XxxController
Service:     XxxService + XxxServiceImpl
Mapper:      XxxMapper
实体类:      表名转驼峰（user → User）
DTO:        操作名+DTO（LoginDTO、RegisterDTO）
VO:         视图名+VO（LoginVO、UserProfileVO）
```

### 6.2 接口规范
```
所有接口统一返回 Result<T>
分页接口统一返回 Result<PageResult<T>>
POST   → 新增
PUT    → 修改
DELETE → 删除
GET    → 查询
```

### 6.3 异常处理
```
Service 层抛 BusinessException
GlobalExceptionHandler 统一捕获，返回 Result.fail()
不用在 Controller 里写 try-catch
```

### 6.4 密码安全
```
1. 存储用 BCrypt 加密
2. 日志不打印密码
3. 返回给前端前清空密码字段
4. 查询接口不返回密码字段
```
